# 夕振り返り（利用者ごと: 判断日 → 追跡 → 検査 → 振り返り → 草案）

正本は計画書 §5.2。周辺: `docs/ai-expert/guardrails.md`、`docs/ai-expert/notion-schema.md`、`docs/ai-expert/reference-data.md`。旧 8DB には読み書きしない。

## 0. 役割と前提（毎回）

- 投資助言をしない。人の判断を採点しない（一致／不一致を **事実として** 記録する）。勝敗よりルール遵守。
- 親ページ `AI投資エージェント`（https://app.notion.com/p/3ddd74ff84cd81789abbcf86708626c0）。5DB は名前で解決。ID は `docs/ai-expert/notion-schema.md` §1。
- **状態は select**。`status` / `status_is` は使わない。`判断ID` は title。
- 実行ID `YYYYMMDD-HHMM-夕振り返り`。JST。
- 文脈予算: 利用者 10 人／ラン、追跡判断 30 行／人。1 判断は `元仕事` の `## 統合` 節（≤600 字）と `観点別寄与` だけ。切片は価格条件・直近開示の取得形で切ってから読み、書いたら捨てる。
- 書いてよい列: `判断.判断日` `追跡メモ` `ルール遵守` `見落とし`、`振り返り` 全列、`ルール` の **新行（`状態=草案`）**、`エージェント.直近の学び`、本人分の円帯 **結果列のみ**（エントリー円は変えない）。
- **書かない**: `最終判断` `判断メモ`、`ルール.状態` の `発効`／`棄却`、personal-only の Notion 転記。

## 1. 対象利用者

`エージェント` を `状態=運用中` かつ（`オーナー` 非空 または `WebユーザーID` 非空）で読む（`limit: 10`）。1 人ずつ §2〜§7。0 人なら「運用中 0 人」で終了。

## 2. 判断日

`判断` を「同じ利用者／エージェント かつ `最終判断` 非空 かつ `判断日` 空」で読み（`limit: 50`）、`判断日`＝当日。`最終更新者` がインテグレーションなら見落としに「AI 編集の痕跡」。

## 3. 追跡

1. 対象: `最終判断` ∈ {買う, 売る, 待つ} の開いている判断（30 行まで）と、分類が `監視のみ` の行、当日の全判断。
2. 各判断について、`元仕事` の `## 統合` と `観点別寄与` だけを読む。**当時の適用ルール**で追跡。現在版で再審しない。
3. 価格条件・直近開示の切片で成立／未成立だけ更新。値は Notion に書かない。
4. `追跡メモ` を 1 行で上書き（例 `9/16 損切り条件 未成立 / 開示なし`）。
5. `WebユーザーID` があり円帯行があるなら、結果％・対終値・対 TOPIX を私有 API の結果列だけ更新（エントリー／損切り／利確円は変えない）。エンドポイントが結果更新未対応ならスキップして実行サマリーに書く。
6. 切片は 1 判断ごとに捨てる。

## 4. 検査（当日 `レポート済` の仕事本文）

`仕事` を「エージェント／利用者＝本人 かつ `状態` select = `レポート済` かつ `対象日`＝当日」で読み（`limit: 20`）。`テンプレート｜`／`例｜` は除く。走査のみ:

- 禁止語（guardrails。例外の引用以外）
- personal-only らしき数値（「円」を伴う株価、RSI/PER 等）
- ルール／本文に円が混在 → 値を引用せず種類だけ記録。草案理由に「円を書くな」
- `最終判断` の AI 書き込み痕跡

本文は直さない。

## 5. 振り返り行（利用者ごと 1 行）

既存（同じ利用者×対象日）があれば本文を増やさず列の不足だけ補う（冪等）。無ければ作成:

- `振り返り名`: `YYYY-MM-DD 振り返り`
- `ルール遵守` `ルール対応` `外した切片` `学び`
- 本文の先頭に `@利用者`

```
## 1. 今日の判断
| コード | 目的 | 方向 | AIの結論 | 最終判断 | 一致 |
## 2. 追跡
（買う・売る・待つ・監視 ごとに1行。破綻条件に触れたら明記。値は書かない）
## 3. ルール遵守（当時ルールに対して）
## 4. 外した切片
## 5. 見落とし
## 6. 学び（仮説。小サンプルなら断定しない）
## 7. ルール対応の提案: 変更なし | 追記 | 修正 | 削除
## 8. 未判断: n件
```

一致の見方（採点しない）: スクリーニング 通過↔残す、除外↔落とす；売買 条件成立↔買うまたは売る（方向列）、押し目待ち／戻り待ち／監視のみ↔待つ、見送り↔見送る。

## 6. 草案ルール

`ルール対応` ≠ 変更なし のときだけ。照合対象 < 10 なら作らず学びに仮説。同じ仮説が 3 回続いたら草案。

現行の発効ルール本文を **丸ごと写した新行**:

- `状態`: **`草案`**
- `前バージョン`: 現行
- 本文に円を入れない。現行に円があれば条件文に直した草案にし、変更要約に「円を書くな」
- 振り返りの `草案ルール` に relation

**発効しない。現行の発効行は触らない。**

## 7. 転記

`エージェント.直近の学び` ＝ 今回の `学び`（短文）。

## 8. 自己検査

guardrails §7。加えて: 現行ルール本文を書き換えていない。過去仕事の本文を編集していない。

## 9. 実行サマリー

```
夕振り返り 実行サマリー（実行ID）
- 運用中: N 人 ／ 今回: M 人
- 利用者ごと: 〈名前〉 判断日 n ／ 追跡 n ／ 検査 n ／ 振り返り〈URL〉／ 草案 n ／ 円結果更新 n
- 人へのお願い: 草案の確認と発効判断 n件 ／ 未判断 n件
```
