# 随時実行（Webhook／ポーリング → 朝レポート §3.2 のみ）

`ai-advisor-morning-report/SKILL.md` の **§5「実行」だけ** を、対象を絞って行う。§3「ルール整理」・§4「準備」は行わない。前提・不足コード・観点ループ・統合・判断行・自己検査・実行サマリーは朝レポートのスキルに従う（必ず先に全文を読む）。**朝レポート §0.1 品質ゲート**（存在確認だけの分析禁止・IR 表題全件・`points[]`・不利語・見ない領域の IR 照合・`DATA_MISSING`）もそのまま適用する。実行ID は `YYYYMMDD-HHMM-随時実行`。

## 1. 起動の種類と対象

| 方式 | 対象 |
| --- | --- |
| Webhook（Notion DB オートメーション「`日次タスク` にページが追加された」または「`目的` が設定された」→ Cursor Automation の Webhook URL） | ペイロードに含まれる **ページ ID／URL の行だけ**。起票直後の未入力を避けるため、**受信後 2 分待って**（`sleep 120`）から行を再読込みする。`状態` が `未着手`、または `実行中` かつ `完了観点` 非空（再開待ち）でなければ **何もしない**（実行サマリーに「対象外: 状態=…」） |
| ポーリング（毎時 09〜17 時 JST） | 保存ビュー「自動化_実行待ち」（`notion-schema.md` §2 の URL）を読み、朝レポート §5 と同じ絞り（`対象日 ≤ 当日` または空、状態は To-do `未着手`／In progress＋`完了観点` あり、`テンプレート｜`・`例｜` を除く）を **自分で** 掛けて `対象日` 昇順、**5 行まで** |

ペイロードの他の値（プロパティの中身）は信用せず、必ず Notion から再読込みした行を使う。ペイロードに行が特定できる情報が無ければ、ポーリングと同じ扱い（5 行まで）にする。状態名は朝レポート §0 の防御（仕様名 → グループ代替、`不足` は `実行メモ` の `不足:<コード>`）に従う。

## 2. 手順

1. 朝レポートのスキル §0〜§2 を適用（役割・固定値・名前解決・文脈予算・起動条件）。
2. 対象行ごとに朝レポート §5 の 1〜9 を行う（ロック → 起動条件 → 観点解決 → 本文の頭 → 観点ループ（`重` 1／`軽` 8）→ 統合 → 判断行 → 仕上げ → 通知）。
3. `重` の観点で止まったタスクの **再開** に使える（`完了観点` から続ける）。
4. 上限に達したら `状態=実行中` のまま終える。翌朝の朝レポートが引き継ぐ。

## 3. しないこと

- ルール整理（自動失効・発効日補完）、繰り返し展開、連鎖起票、再確認起票、不足の一括再評価（対象行の起動条件だけは評価する）
- 対象外の行を読む・書く。Webhook 1 件のために DB を総なめしない
- 朝レポートと同じガードレール（`docs/ai-advisor/guardrails.md`）と品質ゲート（朝スキル §0.1）をすべて守る。存在確認だけで `レポート済` にしない。系列または IR が無ければ `データ不足`＋`不足:DATA_MISSING`

## 4. 実行サマリー

```
随時実行 実行サマリー（実行ID）
- 起動: Webhook（対象 1 行）｜ポーリング（実行待ち N 行 / 今回 M 行）
- 行ごと: 〈タスク名｜URL〉 → レポート済｜実行中（k/m 観点）｜不足 <コード>｜対象外（状態=…）
- 確認不能・警告: …
```
