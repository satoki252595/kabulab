# 日次振り返り（過去レポートのレビュー → 振り返り → ルール草案）

Automation「AI専属アナリスト｜日次振り返り」の本体手順。毎日 1 回、未振り返りの `日次レポート`（当日分＋過去分）を **レポート作成時の `適用ルール`** に照らしてレビューし、`振り返り` 行を書く。学びは `学び` 行に、ルール変更は **草案** として `ルール` に新しい行で提案する。発効は人間がする。

## 0. 最初に読むもの（毎回）

1. `docs/ai-advisor/guardrails.md` — 絶対ルール
2. `docs/ai-advisor/notion-schema.md` — DB ID・ビュー・プロパティ名・状態値・実行パラメータ（上限）。**ID が `TODO` の DB には書き込まない**
3. `docs/ai-advisor/reference-data.md` — 出典タグ（personal-only / no-store を書かない）と観点のスライス
4. Notion MCP `fetch` で `REPORTS` / `REVIEWS` / `RULES` / `LEARNINGS` / `TASKS` / `DECISIONS` のデータソースを取得し、プロパティ名がスキーマ表と一致することを確認する（スキーマ確認のみ。行データはここで読まない）

絶対ルール（抜粋）:

- `ルール` の `状態` を `発効` / `失効` にしない。既存ルール行の本文を書き換えない。草案は **新しい行**（`状態=草案`）としてだけ作る。
- `最終判断` 行を作らない・編集しない（読むだけ）。
- 過去 `日次レポート` の数字・本文を書き換えない。誤りは `振り返り` に書く。
- 評価は **その時点の `適用ルール`** で行う。現在の発効ルールで再審しない。
- **データ全体を読まない。** レポートは 1 件ずつ（その 1 ページ＋適用ルール 1 ページ＋根拠知識 `limit` 付き）読み、所見を `振り返り` に追記してから次へ。`日次レポート` / `知識` / `ルール` DB の総なめ、`limit` なしの取得、全ページ送りをしない。
- personal-only の値（株価・PER/PBR・RSI・スコア・市場区分・JPX 業種・信用残高）とみんかぶ由来の掲載文を `振り返り` / `学び` / 草案 / コメントに書かない（レポートに出ていたら **違反として指摘** する）。
- 禁止語（`買う` `今すぐ買う` `おすすめ` `推奨` `必ず` `確実`）を書かない。注文しない。リポジトリを変えない。PR を作らない。Slack へ出さない。

## 1. 対象レポートの取得

1. `REPORTS` のビュー「自動化_未振り返り」（`完了=✓` かつ `振り返り` relation が空）を view モード（`page_size: MAX_REPORTS_PER_REVIEW`）で **1 ページ目だけ** 読む。ビュー URL が `TODO` なら rows モードで同条件をフィルタし `limit: MAX_REPORTS_PER_REVIEW`。`対象日` 昇順。ここで持つのは **`レポート名` / URL / `目的` / `対象日` / `利用者` / `適用ルール` / `元タスク` の参照だけ**（本文は §2 で 1 件ずつ）。
2. `投資判断（売買計画）` のレポートは、`元タスク.最終判断` または `DECISIONS` で `元レポート` が当該レポートの行を探す。
   - 見つかれば対象に含める（人間の判断とセットで振り返る）。
   - 見つからず、`対象日` から `DECISION_WAIT_DAYS` 日以内 → 今回は **保留**（実行サマリーに「最終判断待ち」と書く）。
   - 見つからず、`DECISION_WAIT_DAYS` 日を超えた → 対象に含め、`振り返り` に「最終判断なし（未記入）」と記録する。
3. 先頭から `MAX_REPORTS_PER_REVIEW` 件を今回の対象にし、残りは次回に回す。
4. 対象 0 件なら何も書かずに「未振り返り 0 件」で終了する。
5. 対象を **`利用者`（空なら `適用ルール.オーナー`、それも空なら「共通」）ごと** にグループ化する。1 グループ＝`振り返り` 1 行（複数レポートを 1 行にまとめてよい）。

## 2. レポートごとの読む順（1 件ずつ。読む → 所見を追記 → 捨てる）

グループの `振り返り` 行を **先に空で作り**（§4 のプロパティ、本文は「対象一覧表」の見出しだけ）、レポートを 1 件処理するごとに本文へ所見を追記する。1 件のために読むのは次のスライスだけ:

1. `日次レポート` **その 1 ページ**（本文とプロパティ: `目的`, `対象日`, `適用ルール`, `対象銘柄`, `根拠知識`, `変化`）
2. `適用ルール` **その 1 ページ**（**そのバージョン**。`上位` を辿って現在の発効版と違っても、評価には当時版を使う。読む見出しはレポートの目的に対応する節と「6 評価・振り返りの見方」）
3. `根拠知識` — rows モードで `元タスク` または `銘柄`＋`基準日` で絞り `limit: MAX_KNOWLEDGE_PER_REPORT_REVIEW`。列は `種別`, `データ品質`, `出典`, `基準日`, `一過性` だけ
4. 同じ `目的`・同じ `適用ルール` の **直前 1 件** のレポート（rows モード `limit: 1`、`対象日 desc`、当該より前）。本文は「入替」または「推論」節だけ（反復と差分の一貫性）
5. `投資判断` なら `最終判断` 行 **1 件**（`最終判断`, `判断日`, `判断メモ`, `反証条件`）
6. 既存の `振り返り`・`学び` は **タイトル検索だけ**（`notion-search` を論点キーワードで `page_size: 5`）。本文は読まない（同じ論点の重複提案を避けるためのタイトル確認）

所見を追記したら、このレポートの本文・知識・ルール本文は以後参照しない（次のレポートで必要なら再度そのページだけ読む）。

## 3. レポートごとの評価項目

| 項目 | 見ること | 記録先 |
| --- | --- | --- |
| ルール遵守 | 適用ルールの各節（選定基準 / 除外 / 必ず見る項目 / IF-THEN / サイズ）に沿っているか。○ / × / 混在 と、×の箇所 | `ルール遵守`、本文 |
| 語彙・免責 | 禁止語がないか、AI所見と材料分類の語を使っているか、免責文があるか。違反は **本文を直さず** 指摘する | `見落とし`、本文 |
| ライセンス境界 | personal-only の値（株価・PER/PBR・RSI・スコア・市場区分・JPX 業種・信用残高）やみんかぶ由来の掲載文がレポート・知識に書かれていないか。書かれていれば **値を引用せずに** 「〈節〉に personal-only の値」と指摘する（人間が削除する） | `見落とし`、本文 |
| 観点の遵守 | 観点ごとの要約が上限内か、`確認不能（観点の上限）` が多発していないか（上限見直しの提案材料） | 本文「観点の状態」 |
| 事実の裏取り | 数字に出典＋基準日があるか、`確認不能` の扱いが正しいか、`根拠知識` の `データ品質` に `要確認`/`欠損` が残っていないか | `見落とし` |
| 反証先行 | 企業分析・投資判断で「買わない理由 3 つ」が推論より前にあるか | `見落とし` |
| 一過性 | 一過性利益・急騰が減点として扱われているか | `見落とし` |
| 反復性 | 同じ条件で前回と同じ手順になっているか。「変化なし」で判断を求めていないか | 本文 |
| 事後対比（投資判断のみ） | `最終判断` と、その後の株価・開示の推移を一次情報で確認できる範囲で対比する。取れなければ `確認不能`。サンプルが少なければ `小サンプル=✓` | `ベンチマーク対比`, `小サンプル` |
| 人間の最終判断（読むだけ） | ルールの IF-THEN と判断が整合しているか。整合していなくても **評価はしない**（人間の権限）。事実として記録する | 本文 |

## 4. `振り返り` 行の作成

グループごとに `REVIEWS` へ 1 行（`notion-create-pages`）:

- `振り返りID`: `YYYY-MM-DD 振り返り`（利用者があれば ` 〈名前〉` を付ける）
- `利用者`: グループの利用者（空なら空）
- `対象日`: 実行日（JST）
- `対象レポート`: 今回レビューしたレポート
- `目的フィルタ`: 含まれた目的
- `ルール遵守`: 全レポート ○ → `○`、全 × → `×`、混在 → `混在`
- `見落とし`: 最重要の見落としを 1〜3 行
- `ルール対応`: `変更なし` / `追記` / `修正` / `削除`（§5 の判断）
- `対象ルール`: 変更を提案する既存ルール行（変更なしなら空）
- `草案ルール`: §5 で作った草案行（作らなければ空）
- `ベンチマーク対比`: 投資判断があれば要約、なければ `確認不能` または「対象なし」
- `小サンプル`: 対比の根拠が 3 件未満なら `__YES__`

本文（Notion Markdown。1・2 は §2 のループで 1 件ずつ追記、3〜6 は全件の所見だけから最後に書く）:

1. **対象一覧表** — `レポート` / `目的` / `適用ルール` / `ルール遵守` / `見落とし要約`（1 レポート 1 行を追記）
2. **レポート別の所見**（各 3〜6 行、`MAX_SUMMARY_CHARS_PER_AXIS` 以内。引用は短く、レポート本文を貼り直さない。personal-only の値は引用しない）
3. **反復の状態** — 同じ条件を何回回せたか、途中でルールや手順が変わっていないか
4. **観点の状態** — `確認不能（観点の上限）` が出た観点と回数（上限見直しは人間）
5. **ルールへの提案** — 変更なし / 追記 / 修正 / 削除 と理由。草案を作った場合はリンク
6. **学び候補** — §6 で作る `学び` の要約
7. 免責文 1 行

## 5. ルール草案（作るときの条件と作り方）

作る条件（いずれか）:

- 同じ見落とし・同じ遵守×が **2 回以上** 繰り返されている
- ルールの条件が一次情報で確認不能な項目に依存している（確認可能な条件へ言い換える提案）
- 人間の `判断メモ` / `反証条件` にルール化を示す記述がある
- 人間が `振り返り` や `日次タスク` のコメントで変更を求めている

作らない条件:

- 1 回だけの事象、サンプル 3 件未満の事後対比だけに基づく変更
- 「当たったか」だけを理由にした緩和・強化（評価軸は反復可能性）
- 発効中ルールの数値をレポートの結果に合わせて後追いで動かすだけの変更

作り方（`RULES` に **新しい行**）:

- `ルールID`: 元ルール ID に `-draft-YYYYMMDD` を付ける（例 `R-001-v1.2-draft-20260915`）
- `利用者` / `オーナー` / `専属エキスパート` / `種別` / `対象目的`: 元ルールからコピー
- `バージョン`: 元の次（例 `v1.3`）
- `状態`: **`草案`**（これ以外を設定しない）
- `上位`: 元ルール行
- `根拠振り返り`: 今回の `振り返り` 行
- `根拠学び`: §6 の `学び` 行
- `発効日`: 空（人間が入れる）
- `変更要約`: 「追記 / 修正 / 削除: 〈1 行〉」
- 本文: 元ルール本文を全文コピーし、変更箇所を `> 変更（草案）:` の引用ブロックで示す。見出し「7 変更理由」に根拠（レポート・振り返りへのリンク）を書く

削除の提案は「本文からその条項を外した草案」として書く。既存行を `失効` にしない。

## 6. `学び` 行の作成

振り返りで得た再利用可能な知見を `LEARNINGS` に 1〜3 行:

- `学びタイトル`: 1 行
- `利用者` / `専属エキスパート`: グループから
- `根拠振り返り`: 今回の行
- `確かさ`: 初回は `仮説`。同じ学びが実地で 3 回以上支持されたら `実地支持`
- `ルール化`: 草案を作った → `草案済`、作っていない → `未提案`（`発効済` / `棄却` は人間が付ける）
- `提案ルール`: 草案行
- `範囲`: 個人固有なら `個人のみ`、他メンバーにも当てはまりそうなら `共通テンプレ候補`

同じ論点の `学び` が既にあれば新規作成せず、本文で参照する。

## 7. `日次タスク` の更新

レビューしたレポートの `元タスク` に対して:

- `振り返り` relation に今回の `振り返り` 行を追加
- `状態` を `DONE_STATUS`（`完了`）に更新

保留（最終判断待ち）のタスクは触らない。

## 8. 自己検査（保存前）

- 既存 `ルール` 行の `状態` / 本文を変えていない。草案の `状態` が `草案` である
- `最終判断` 行を作成・編集していない
- 過去 `日次レポート` を編集していない
- 評価に使ったルールが各レポートの `適用ルール` である（現在版ではない）
- 禁止語がない。免責文がある
- personal-only の値・みんかぶ由来の掲載文を `振り返り` / `学び` / 草案 / コメントに書いていない
- レポートを 1 件ずつ、`limit` 付きのスライスで読んだ（DB の総なめ・全ページ送りをしていない）
- リポジトリ変更・PR・外部投稿がない

## 9. 実行サマリー

```
日次振り返り 実行サマリー（JST YYYY-MM-DD HH:MM）
- 未振り返り: N 件 / 今回: M 件 / 保留（最終判断待ち）: P 件 / 次回へ: K 件
- 振り返り行: 〈URL〉…（グループ別）
- ルール草案: 〈ルールID〉→〈URL〉（追記/修正/削除）… または「なし」
- 学び: N 件
- 人間へのお願い: 草案の確認と発効判断 / 最終判断の未記入 …
```

## 10. 未配線・スキーマ不一致のときの振る舞い

`REPORTS` / `REVIEWS` / `RULES` / `LEARNINGS` のいずれかが `TODO` またはプロパティ不一致なら、読み取り確認だけ行い、書き込みをせずに実行サマリーへ理由を書いて終了する。
