# オンボーディング確認（新しい利用者の最小入力チェック）

Automation「AI専属アナリスト｜オンボーディング確認」の本体手順。計画書のオンボーディング順（**専属 1 行 → 制約4項目 → ルール v1 発効 → 日次タスクを 1 行書いてループを見る**）に沿って、新しい `専属エキスパート` 行に足りないものを **検査して知らせる** だけの軽い自動化。値を埋めない、ルールを作らない、`状態` を変えない。

## 0. 最初に読むもの（毎回）

1. `docs/ai-advisor/guardrails.md`
2. `docs/ai-advisor/notion-schema.md`（`EXPERTS` / `RULES` / `TASKS` の ID・ビュー・プロパティ名）
3. Notion MCP `fetch` でプロパティ名を確認

絶対ルール（抜粋）: 設定列（制約4項目・低確信度のサイズ・ウォッチ上限・既定の目的・状態）を書き換えない。`ルール` を作らない・発効しない。`日次タスク` を作らない。コメント以外を書かない。禁止語を書かない。リポジトリ変更・PR・外部投稿をしない。

## 1. 対象行の取得

1. `EXPERTS` のビュー「自動化_設定中」（`状態=設定中` または作成 14 日以内）を view モード（`page_size: 20`）で **1 ページ目だけ** 読む。ビュー URL が `TODO` なら rows モードで同条件をフィルタし `limit: 20`。
2. 直近 24 時間以内に自分（この Automation）が同じ内容のコメントを付けた行はスキップする（同じ指摘を毎日繰り返さない。前回コメントと差分があるときだけ再コメント）。コメントは `notion-get-comments` でその行のものだけ読む。
3. 対象 0 件なら何も書かずに終了する。
4. 検査 6〜9 で `RULES` / `TASKS` を読むときも、その専属（またはオーナー）で絞った rows モード `limit: 5` だけ。DB の総なめをしない。

## 2. 検査項目（行ごと）

| # | 検査 | 合格条件 | 不足時の文言 |
| --- | --- | --- | --- |
| 1 | オーナー | `オーナー` に 1 人 | 「オーナー（この専属の対象メンバー）を 1 人設定してください」 |
| 2 | 制約4項目 | `投資期間` / `1銘柄あたり金額` / `許容損失` / `見ない領域` がすべて非空 | 「制約〈項目名〉が空です。空の制約のままスクリーニングは走りません」 |
| 3 | 低確信度のサイズ | 非空（推奨初期値「通常の半分」） | 「低確信度のサイズが空です（例: 通常の半分）」 |
| 4 | ウォッチ上限 | 数値 > 0 | 「ウォッチ上限（スクリーニング件数の上限）を入れてください」 |
| 5 | 既定の目的 | 3 値のいずれか | 「既定の目的（スクリーニング / 企業分析 / 投資判断（売買計画））を選んでください」 |
| 6 | 発効ルール v1 | `RULES` に、`状態=発効` かつ（`専属エキスパート`=この行 または `オーナー`=この行のオーナー または `種別=共通テンプレ`）かつ `対象目的` が `既定の目的` を含む行が 1 つ以上 | 「〈既定の目的〉に使える 発効 ルールがありません。ルール v1 を作り 状態=発効 にしてください（共通テンプレを使う場合は 現行ルール に紐づけてください）」 |
| 7 | ルール本文 | 6 のルールに、目的に対応する見出し（スクリーニング: 1・2 / 企業分析: 2・3 / 投資判断: 4・5）と「6 評価・振り返りの見方」がある | 「ルール〈ID〉に見出し〈…〉がありません」 |
| 8 | 現行ルール | `現行ルール` relation が 6 のルールを指す（任意だが推奨） | 「現行ルール に発効ルールを紐づけると、日次タスクの入力が短くなります」 |
| 9 | 最初の日次タスク | `TASKS` に `専属エキスパート`=この行 または `利用者`=オーナー の行が 1 つ以上 | 「最初の 日次タスク を 1 行書くとループが始まります（目的 / ルール / 対象日、企業分析・投資判断なら対象銘柄）」 |

検査 1〜6 が **必須**、7〜9 は **推奨**。

## 3. コメント

`notion-create-comment` で `専属エキスパート` 行にコメントを 1 件（見出し＋箇条書き）:

```
オンボーディング確認（JST YYYY-MM-DD）
必須で不足: 〈#2 制約: 許容損失〉〈#6 発効ルール〉…   ← なければ「必須はすべて揃っています」
推奨: 〈#9 最初の日次タスク〉…
次の一手: 〈計画書の順で、最初に埋めるべき 1 つ〉
必須が揃ったら 状態 を 運用中 に変えてください（この自動化は状態を変えません）。
```

不足がひとつもなければ「必須・推奨ともに揃っています。状態を 運用中 にすると日次ループが通常運用になります」とだけ書く（前回と同じなら書かない）。

`利用者` は任意という製品方針のため、`日次タスク.利用者` が空でも不足とはしない。

## 4. 実行サマリー

```
オンボーディング確認 実行サマリー（JST YYYY-MM-DD HH:MM）
- 設定中: N 行 / コメント: M 行 / スキップ（前回と同じ）: K 行
- 行ごと: 〈名前〉 → 必須不足 a 件 / 推奨不足 b 件
```

## 5. 未配線・スキーマ不一致のときの振る舞い

`EXPERTS` / `RULES` / `TASKS` のいずれかが `TODO` またはプロパティ不一致なら、コメントを付けずに実行サマリーへ理由を書いて終了する。
