# 随時実行（Webhook／ポーリング → 朝レポートの実行のみ）

`ai-expert-morning-report/SKILL.md` の **§5「実行」だけ** を、対象を絞って行う。§3「ルール整理」・§4「準備」は行わない。前提・不足コード・切片ループ・統合・判断行・円 POST・自己検査は朝レポートのスキルに従う（必ず先に全文を読む）。実行ID は `YYYYMMDD-HHMM-随時実行`。旧 8DB には読み書きしない。`仕事.状態` は **select**（`status` ではない）。`判断ID` は title。

Web の「今すぐ調べる」や銘柄指定の売買判断がここに入る。

## 1. 起動の種類と対象

| 方式 | 対象 |
| --- | --- |
| Webhook（Notion `仕事` にページが追加された／`目的` が設定された → Cursor Automation Webhook） | ペイロードの **ページ ID／URL の行だけ**。受信後 2 分待つ（`sleep 120`）して再読込み。`状態` が `未着手`、または `実行中` かつ `完了切片` 非空でなければ何もしない |
| ポーリング（毎時 09〜17 時 JST） | 実行待ちを朝レポート §5 と同じ絞りで **5 行まで** |

ペイロードの他の値は信用せず、必ず Notion から再読込みする。行が特定できなければポーリングと同じ（5 行まで）。

## 2. 手順

1. 朝レポートのスキル §0〜§2 を適用（役割・名前解決・文脈予算・起動条件）。
2. 対象行ごとに朝レポート §5 を行う（ロック → 起動条件 → 本文の頭 → 切片ループ → 統合 → 判断行 → 円 POST → 仕上げ）。
3. `重` 切片で止まった仕事の再開に使える。
4. 上限に達したら `状態=実行中` のまま終える。翌朝が引き継ぐ。

## 3. しないこと

- ルール整理、繰り返し展開、連鎖起票、再確認起票、ウォッチ自動起票、不足の一括再評価（対象行の起動条件だけは評価する）
- 対象外の行を読む・書く。Webhook 1 件のために DB を総なめしない
- 旧 8DB への書き込み、発注、リポジトリ変更、シークレット出力

## 4. 実行サマリー

```
随時実行 実行サマリー（実行ID）
- 起動: Webhook（対象 1 行）｜ポーリング（実行待ち N 行 / 今回 M 行）
- 行ごと: 〈仕事名｜URL〉 → レポート済｜実行中（k/m 切片）｜不足 <コード>｜対象外（状態=…）
- 円 POST: 成功 n / 失敗 n / スキップ n
- 確認不能・警告: …
```
