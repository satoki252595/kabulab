# 夕振り返り（利用者ごと: 判断日 → 追跡 → 検査 → 振り返り → 草案）

正本は Project の `internal/automation-spec.md` §5（GitHub 版が入れば `docs/ai-advisor/plan-and-design.md`）。矛盾したら正本が勝つ。周辺文書: `docs/ai-advisor/guardrails.md`、`docs/ai-advisor/notion-schema.md`、`docs/ai-advisor/reference-data.md`（観点「価格条件」「直近開示」の取得形）。

## 0. 役割と前提（毎回）

- 役割: 自己成長するAI投資家アドバイザーの自動化。投資助言をしない。人の判断を採点しない（一致／不一致を **事実として** 記録する）。
- 固定値: 親ページ `https://app.notion.com/p/3dad74ff84cd80c4956feaf9255de7e1`。8DB は名前で解決し、`notion-schema.md` §1・§2 の ID・ビュー URL（2026-09-15 照合済み）と突き合わせる。
- 状態の解決（防御）: `日次タスク.状態` の「レポート済」は仕様名を第一に、無ければ Complete グループの選択肢（現状 `完了`）で読む。rows モードのフィルタは `status_is` の `is_group: complete`（`notion-schema.md` §3.1）。日付フィルタ（`対象日`・`判断日`）はビューに頼らず **自前で** 掛ける。
- 実行ID `YYYYMMDD-HHMM-夕振り返り`。時刻は JST。
- 文脈予算: 利用者 10 人／ラン、追跡判断 30 行／人。1 判断につき読むのは `元タスク` の `## 統合` 節（≤600 字）と `観点別寄与` だけ。当日レポートの検査は本文を **走査**（禁止語・数値パターン）するだけで要約を作らない。切片は観点「価格条件」「直近開示」の取得形（`reference-data.md` §4）で、`jq` で切ってから読み、書いたら捨てる。
- 無人実行: 質問しない。迷えば `確認不能`。
- 書いてよい列: `判断.判断日` `判断.追跡メモ` `判断.次回確認日`、`振り返り` の全列と本文、`ルール` の **新行（`状態=草案`）**、`専属エキスパート.直近の学び`。**`判断.最終判断`・`判断メモ`、`ルール.状態` の `発効`／`棄却`、`分析観点`・`参照資産` は書かない。**

## 1. 対象利用者

`専属エキスパート` を `状態=運用中` かつ `オーナー` 非空 で読む（rows モード、`limit: 10`。共通行は除く）。1 人ずつ §2〜§7 を行う。0 人なら「運用中 0 人」で終了。

## 2. 判断日（利用者ごと）

`判断` を「`利用者`＝本人 かつ `最終判断` 非空 かつ `判断日` 空」で読み（`limit: 50`）、`判断日`＝当日を書く。`最終更新者` がインテグレーション（自動化ユーザー）なら「AI 編集の痕跡」として §5 の見落としに記録する。

## 3. 追跡

1. 対象: `最終判断` ∈ {監視, 待つ, 買う} の開いている判断（`判断日` 昇順、30 行まで）と、当日の全判断（`判断日`＝当日）。
2. 各判断について、`元タスク` の `## 統合` 節（≤600 字）と `観点別寄与` だけを読む。
3. `買う` は破綻条件を、`待つ` は価格条件を、観点「価格条件」（『kabulab 日足10年』末尾 120 本）と「直近開示」（『kabulab IR Catalog』直近 30 日）の切片で確認する。personal-only は **成立／未成立** のみ。開示は日付・表題・タグを **30 日窓の全件** 読む（先頭 3 件で止めない）。表題/タグに `上場廃止` `整理銘柄` `監理銘柄` `意見不表明` `下方修正` `訂正` `不祥事` があれば追跡メモに「不利語:〈語〉」と書く。404 / 空配列は「データ不足」。存在確認（HTTP 200 / `hasStructuredData`）だけでは追跡しない。
4. `追跡メモ` を 1 行で **上書き**（例 `9/15 破綻条件 未成立 / 開示なし`）。破綻条件に触れた場合は §4 本文「2. 追跡」に明記する。
5. 切片は 1 判断ごとに捨てる。

## 4. 検査（当日 `レポート済` のタスク本文）

`日次タスク` を「`利用者`（空なら `作成者`）＝本人 かつ 状態が Complete グループ（`レポート済`／改名前は `完了`） かつ `対象日`＝当日（date フィルタを自前で指定。`タスク名` が `テンプレート｜`／`例｜` で始まる行は除く）」で読み（`limit: 20`）、本文を走査する:

- 禁止語（`買う` `買い` `買い推奨` `今すぐ` `今すぐ買う` `必ず` `絶対` `爆益` `急騰確実`。例外: 「買う条件」「買わない理由」「人の最終判断＝買う」の引用）
- personal-only の値らしき数値（株価・RSI・PER・PBR・利回り・信用倍率の数字。「円」「%」「倍」を伴う数値で出典が Yahoo/JPX 由来の観点の節にあるもの）
- `判断.最終判断` の AI 書き込み痕跡（§2）
- 観点の節（`## 観点: X`）の数と `完了観点` の不一致、`確認不能（到達不能）` の多発
- **存在確認だけの分析**（`hasStructuredData` だけ / エンドポイント ping / IR 表題が先頭 3 件だけ）なのに `レポート済` になっている
- 対象コードの系列または IR が空なのに滑らかな統合があり、`データ不足` と書いていない（朝スキル §0.1。本文は直さない）
- 不利語（上場廃止 / 整理銘柄 / 監理銘柄 / 意見不表明 / 下方修正 / 訂正 / 不祥事）が表題にあるのに推論より後、または未記載
- 見ない領域が sector 一致だけで、IR の監理/整理/上場廃止を見ていない一覧

見つけたら「見落とし」に **値を引用せず** 場所（タスク・節）と種類だけ書く。本文は直さない。

## 5. 振り返り行（利用者ごと 1 行）

`振り返り` に作成（`notion-create-pages`）:

- `振り返りID`: `YYYY-MM-DD 振り返り 利用者名`
- `対象日`: 当日 ／ `利用者`: 本人 ／ `専属エキスパート`: 本人の行
- `対象タスク`: 当日 `レポート済` のタスク ／ `対象判断`: 当日の判断＋追跡分
- `ルール遵守`: `○` / `×` / `混在` / `該当なし`（当時の `適用ルール` に対して。現在版で再審しない）
- `見落とし`（1 行）、`学び`（1 行）、`ルール対応`（`変更なし` / `追記` / `修正` / `削除`）、`関連観点`（外したと見た観点）、`未判断件数`、`小サンプル`（照合対象 < 10 件で ON）
- 本文の先頭に `@利用者`「振り返りと草案 n件」

本文（見出し順は固定）:

```
## 1. 今日の判断
| 銘柄 | 目的 | AIの結論 | 最終判断 | 一致 | 観点別寄与 |
## 2. 追跡
（監視・待つ・買う の行ごとに1行。破綻条件に触れたら明記）
## 3. ルール遵守（当時ルールに対して）
## 4. 外した観点
（不一致の判断について、寄与が人の判断と逆を向いた観点。関連観点 に relation）
## 5. 見落とし
## 6. 学び（仮説。小サンプルなら断定しない）
## 7. ルール対応の提案: 変更なし | 追記 | 修正 | 削除（草案があればリンク）
## 8. 未判断: n件
```

「一致」の見方: スクリーニング 通過↔残す／要分析、除外↔落とす；企業分析 有利寄り↔投資判断へ進む、中立↔監視、回避寄り↔見送り；投資判断 条件成立↔買う、押し目待ち／監視のみ↔待つ、見送り↔見送る。外れていても採点しない。

## 6. 草案ルール（`ルール対応` ≠ 変更なし のときだけ。`小サンプル` ON なら作らず「学び」に仮説として残す。3 回以上同じ仮説が続いたら草案）

現行の発効ルール（目的ルール、または外した観点の観点ルール。無ければ目的ルール）の本文を **丸ごと写した新行** を `ルール` に作る:

- `ルールID`: `<オーナー名 or 共通> <目的 or 観点:名> v<バージョン+1>`
- `状態`: **`草案`**（これ以外にしない）
- `バージョン`: 現行＋1 ／ `前バージョン`: 現行 ／ `オーナー`・`専属エキスパート`・`対象目的`: 現行と同じ ／ 観点固有なら `対象観点`＝その観点
- `根拠振り返り`: この振り返り ／ `変更要約`: 1 行
- 本文: 該当節に変更を反映し、`## 8. 変更理由` に理由（振り返り・判断へのリンク）

振り返りの `草案ルール` に relation。**発効しない。現行の発効行は触らない。**

## 7. 転記

`専属エキスパート.直近の学び` ＝ 今回の `学び`。

## 8. 自己検査（保存前）

- `判断.最終判断`・`判断メモ` を書いていない。`ルール.状態` を `発効`・`棄却` にしていない。現行ルール本文を書き換えていない
- 草案の `状態` が `草案`、`前バージョン` が現行を指す
- 過去タスクの本文を編集していない（指摘は振り返りに）
- 禁止語がない（`買う` `今すぐ買う` を含む）。personal-only の値を引用していない（追跡メモも成立／未成立）
- 1 判断につき統合節と寄与だけ、当日タスクは走査だけ（DB 総なめ・`limit` なし取得をしていない）
- リポジトリ変更・PR・外部投稿がない。シークレット値を出力していない

## 9. 実行サマリー

```
夕振り返り 実行サマリー（実行ID）
- 運用中: N 人 ／ 今回: M 人
- 利用者ごと: 〈名前〉 判断日 n ／ 追跡 n（破綻条件に触れた n）／ 検査 n タスク（見落とし n）／ 振り返り〈URL〉／ 草案 n〈URL〉／ 小サンプル: ON|OFF
- 人へのお願い: 草案の確認と発効判断 n件 ／ 未判断 n件 ／ AI 編集痕跡 n件
```

## 10. 未解決・不一致のときの振る舞い

8DB の名前解決やプロパティ名が合わなければ、書き込みをせずに理由を実行サマリーに書いて終了する（`ai-advisor-morning-report` §10 と同じ）。
