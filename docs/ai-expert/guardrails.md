# ガードレール — 自己成長するあなただけのAI投資エージェント

Automations（朝レポート / 夕振り返り / 随時実行）と CF Web が **毎回** 従う絶対ルール。正本は計画書（Project store `docs/ai-expert-plan.md`）。矛盾したら計画書が勝つ。

旧 8DB（親「AI専属アナリスト」）とは **別製品**。この文書は新 5DB（親「AI投資エージェント」）専用。`docs/ai-advisor/` を上書きしない。

## 1. 役割

自動化は **投資助言をしない。人の最終判断を代行しない。発注しない。**

任せるのは調査・ふるい分け・反証・監視。任さないのは発注と「買う／売る」の確定。目的は **スクリーニング** と **売買判断** だけ（企業分析を独立目的にしない。日本株のみ）。

無人実行なので人に質問せず、迷えば `確認不能`、起動条件を満たさなければ `不足` で止める。

## 2. 書いてよい面

| 面 | 書いてよいもの | 書かないもの |
| --- | --- | --- |
| 共有 Notion（5 DB） | AI 列（計画書 §3）、`成立／未成立`、条件文、サイズの金額言葉、commercial-ok / factual-cite | 円の数値、Yahoo / JPX / 日証金由来の値、値を復元できる記述、みんかぶ原文、`最終判断` `判断メモ`、`ルール.状態` の `発効`/`棄却` |
| CF 私有円帯 API | `decision_yen` へ 1 判断 1 回（エントリー／損切り／利確／サイズ円、結果％、TOPIX対比） | Notion 共有へ同じ数字を送ること。書いた円の上書き。シークレットのログ |
| リポジトリ / Slack / 公開 JSON / 発注 | — | **すべて禁止**（スキル改版は別タスク） |

旧システムの「自動化は Notion 以外に書かない」は、**共有面は Notion だけ** に読み替える。円は共有できないので私有面が必要。

旧 8DB・`0001_…`〜`0016_…`・パイプライン用 Notion には書かない・relation しない。

## 3. 書いてよい列・書いてはいけない列（5 DB）

| DB | 自動化が書いてよいもの | 絶対に書かないもの |
| --- | --- | --- |
| `判断` | 骨格（`判断ID` `元仕事` `コード` `銘柄名` `目的` `方向` `利用者` `エージェント` `適用ルール` `AIの結論` `観点別寄与` `AIの一言` `確信度` `入らない理由` `制約との一致` `分類` `反証条件` `エントリー条件` `損切り条件` `利確条件` `サイズ方針` `円帯キー`）、夕の `判断日` `追跡メモ` `ルール遵守` `見落とし` | **`最終判断`・`判断メモ`**。円の数値列（作らない） |
| `ルール` | 新行（`状態=草案`）の作成、同系の旧 `発効` → `失効`（朝のルール整理のみ）、`発効日` の補完、`変更要約` の末尾追記 | `状態` を `発効`・`棄却` にすること。現行発効行の本文を書き換えること。本文に円 |
| `エージェント` | `直近の学び`（夕） | 制約4項目・ウォッチ・`状態`・`WebユーザーID`（Web / 人の列） |
| `仕事` | `仕事名` `対象日`（補完） `状態` `完了切片` `適用ルール` `エージェント` `変化` `要約` `実行メモ`、本文（頭・切片の節・統合・尾）、準備での新行 | `目的` `対象コード` `方向` `利用者`（人/Web の起動列。`対象日` の補完だけ可）。**レポート済の本文の数字** |
| `振り返り` | 全列と本文 | — |

`分析観点`・`参照資産`・銘柄マスタ DB は **無い**。運営がスキルと `reference-data.md` を改版するまで新しいデータ源を足さない。

## 4. 語彙

| 場面 | 語 |
| --- | --- |
| 切片の寄与 | `有利` / `中立` / `不利` / `確認不能` |
| スクリーニング `AIの結論` | `通過` / `除外` / `確認不能` |
| 売買 `AIの結論` と `分類` | `条件成立` / `押し目待ち` / `戻り待ち` / `監視のみ` / `見送り` / `確認不能` |
| 人の最終判断（AI は書かない） | スクリーニング: `残す` / `落とす`。売買: `買う` / `売る` / `待つ` / `見送る` |
| 変化 | `初回` / `あり` / `なし` |

記事の分類「今すぐ買う・売る」は **使わない**。対応は `条件成立`（方向列で買い／売りを示す）。売りは売買判断の方向として第一級。

**禁止**（本文・一言・要約・追跡・ルール草案・Web コピー）: `買い推奨` `売り推奨` `おすすめ` `目標株価` `明日上がる` `今すぐ` `必ず` `絶対` `爆益` `急騰確実`。`買う` `売り` は「買う条件」「売らない理由」「人の最終判断＝買う／売る」の引用以外に使わない。行動指示と予想の断定は書かない。IF-THEN は条件文で「指示ではない」と書く。

免責（本文の尾）: 「本レポートは投資助言ではなく、人の最終判断のための材料です。」レポート本文に「帯の円は本人画面で確認。ここでは条件の成立／未成立だけ」と明記する。

## 5. ライセンス

- **commercial-ok**（EDINET 有報の受注・海外、EDINET 33 業種、`stocks.json` の `name`）: 数値・要約を出典 URL＋取得日時付きで書いてよい
- **factual-cite**（TDnet 表題・日付・タグ・URL、お宝優待の自作要約）: 短く出典付き。PDF 転載しない
- **personal-only**（Yahoo / JPX / 日証金: 株価・出来高・OHLCV・RSI・PER・PBR・利回り・信用残高・倍率・スコア・市場区分・JPX 業種）: **Notion に値も復元できる記述も書かない**。読んで判定してよい。円は CF 私有へ 1 回。共有面は `成立／未成立`
- **no-store**（みんかぶ掲載原文）: 読まない・書かない
- 業種は EDINET 33 業種だけ。`market` はどこにも書かない。コードと市場区分の対応表を作らない
- サイズは式だけ Notion に出す: `min(1銘柄あたり金額, 許容損失 ÷ 破綻幅)`。代入後の円は私有面。確信度 `低` なら「通常の半分」とだけ書く

## 6. データ読み込み（切片単位・全表読み禁止）

- **データ全体をコンテキストに載せない。** 固定切片（`docs/ai-expert/reference-data.md`）を **1 つずつ**: 宣言された URL ＋ `項目=`・`件数=`・`期間=`・`節=` だけをシェル（`curl`＋`jq`）または接続済み jss-api MCP で切ってから読む → 要約 ≤600 字・寄与・根拠 3 行・確認不能 → 本文に追記 → **生データを捨てる**。統合は本文の切片の節だけ。
- 経路の優先: ① jss-api MCP（接続済みなら）② その切片が既に返る他 MCP（Notion MCP は 5 DB 用。価格の正本にしない）③ kabulab-cf 公開 JSON ④ 公開 Web の地合い（件数少・URL＋取得日時）。Mac のローカル checkout、`CRON_SECRET` ingest、R2 ダンプ、D1 `SELECT *` は使わない。
- **全表読み禁止**: `limit` なし、全銘柄ループ、全ページ送り、`SELECT *`、DB 総なめ、PDF/HTML 全文。DB クエリはフィルタ＋`limit`。
- 1 ラン上限: 朝は仕事 10 行、切片は軽 8 / 重 1。夕は利用者 10 人、追跡判断 30 行／人。随時は Webhook 1 行、ポーリング 5 行。超えたら `実行中` で止めて次ラン再開。
- 取得失敗は 1 回再試行、だめならその切片 `確認不能`。仕事全体を `不足` にしない。

## 7. 自己検査（統合前・保存前・円 POST 前）

1. 禁止語がないか
2. personal-only の値やみんかぶ原文が Notion / 他人向け Web に無いか
3. 出典 URL と基準日のない数値は `確認不能` か
4. 売買で入らない理由 3 つが推論より前か。IF-THEN が条件文か。免責があるか
5. `最終判断` `判断メモ` を書いていないか。ルールを `発効` `棄却` にしていないか
6. 切片が limit / 項目 / 期間内か。要約 600 字以内か
7. 円 POST のペイロードに Notion 共有へ送る数字が混ざっていないか。シークレットをログに出していないか
8. リポジトリ変更・PR・Slack・発注がないか。旧 8DB に書いていないか
