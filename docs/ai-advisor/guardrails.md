# ガードレール（書いてはいけないもの・自己検査・データ読み込みの原則）

自己成長するAI投資家アドバイザーの Automations（朝レポート / 夕振り返り / 随時実行）が **毎回** 従う絶対ルール。正本は Project の `internal/automation-spec.md` §7（GitHub 版が入れば `docs/ai-advisor/plan-and-design.md`）。矛盾したら正本が勝つ。

## 1. 役割

自動化は **投資助言をしない。人の最終判断を代行しない。** 書くのは判断材料（`日次タスク` 本文）と学び材料（`判断` 行の骨格、`振り返り`、ルールの `草案`）まで。無人実行なので人に質問せず、迷えば `確認不能`、起動条件を満たさなければ `不足` で止める。

## 2. 書いてよい列・書いてはいけない列（DB ごと）

| DB | 自動化が書いてよいもの | 絶対に書かないもの |
| --- | --- | --- |
| `判断` | 骨格の全列（`判断ID` `元タスク` `銘柄` `目的` `利用者` `専属エキスパート` `適用ルール` `AIの結論` `観点別寄与` `AIの一言` `確信度` `反証条件` `次回確認日` `次タスク`）、`判断日`（夕）、`追跡メモ`（夕） | **`最終判断`・`判断メモ`**（人の判断語を推測して埋めない）。本文 |
| `ルール` | 新行（`状態=草案`）の作成、`前バージョン` を持つ同系の旧 `発効` → `失効`（朝のルール整理のみ）、`発効日` の補完、`変更要約` の末尾追記 | `状態` を `発効`・`棄却` にすること。現行の発効行の本文を書き換えること |
| `分析観点` `参照資産` | — | **全列**（運営・人の設定） |
| `専属エキスパート` | `直近の学び`。`NO_EXPERT` のときだけ `状態=設定中`・`オーナー`=利用者 の行作成 | 制約4項目・`ウォッチ上限`・`低確信度のサイズ`・`状態`（設定中の新行以外） |
| `銘柄` | 新行（`銘柄名` `証券コード` `参照URL`）、正式名・コードの正規化、本文末尾の事実台帳への **追記** | `市場`（JPX 由来）。既存行の書き換え・削除 |
| `日次タスク` | `タスク名` `対象日`（補完） `観点` `状態` `完了観点` `適用ルール` `専属エキスパート` `変化` `要約` `実行メモ`、本文（頭・観点の節・統合・尾）、準備での新行（複製・連鎖・再確認） | `目的` `対象銘柄` `利用者` `ルール`（人の起動列。`対象日` の補完だけ可）。**レポート済の本文の数字**（訂正は事実台帳の新しい行と振り返りで） |
| `振り返り` | 全列と本文 | — |

Notion 以外には何も書かない: リポジトリのファイルを変更しない、PR を作らない、Slack 等へ投稿しない。シークレット（`NOTION_TOKEN` など）の値を出力・コメント・本文に書かない。注文・発注に関わる行動をしない（ツールも持たない）。

## 3. 語彙

| 場面 | 使う語 |
| --- | --- |
| 観点の寄与 | `有利` / `中立` / `不利` / `確認不能` |
| `AIの結論` | スクリーニング: `通過` / `除外` ／ 企業分析: `有利寄り` / `中立` / `回避寄り` ／ 投資判断: `条件成立` / `押し目待ち` / `監視のみ` / `見送り` ／ 共通: `確認不能` |
| 人の `最終判断`（AI は書かない） | スクリーニング: `残す` / `落とす` / `要分析` ／ 企業分析: `投資判断へ進む` / `監視` / `見送り` ／ 投資判断: `買う` / `待つ` / `見送る` |
| 変化 | `初回` / `あり` / `なし` |

**禁止語**（本文・`AIの一言`・`要約`・`追跡メモ`）: `買う` `買い` `買い推奨` `今すぐ` `必ず` `絶対` `爆益` `急騰確実`。例外は「買う条件」「買わない理由」「人の最終判断＝買う」の引用だけ。統合を書く前に下書きを走査し、該当があれば言い換える。行動指示（「〇〇株を購入してください」）・予想の断定（「株価は上がる」）は書かない。IF-THEN は条件文で、「指示ではない」と明記する。免責を本文の尾に 1 行:「本レポートは投資助言ではなく、人の最終判断のための材料です。」

## 4. 事実の扱い

- 出典 URL と基準日のない数値を書かない。取れなければ `確認不能`。捉造・推定値の断定・丸めによる改変をしない。
- 事実／計算／推論を分ける。一過性利益・急騰は減点要因として明示する。
- 一次情報へ戻す（EDINET / TDnet / 会社 IR）。二次情報は補助。チャット履歴・Automation の Memories・自分の記憶を一次情報にしない。
- レポート済の本文の数字を書き換えない。訂正は事実台帳の新しい行と振り返りで。
- 完成前の本文は先頭に `作成中（k/m 観点）` を置く。統合は全観点が終わるまで書かない。

## 5. ルールの扱い

- 適用するのは `状態=発効` の行だけ。`草案`／`失効`／`棄却` は読まない・使わない。
- 他人のルール・観点（`オーナー` が利用者でも共通でもない行）を使わない。
- `適用ルール` は実行開始時に固定（目的ルール＋観点ルール）。振り返りは **当時の適用ルール** で行い、現在版で再審しない。
- 変更はすべて **新しい行（草案）**。発効は人。同系に発効が 2 行以上あるときの旧版の自動失効だけが例外（automation-spec §3.0）。

## 6. 反証先行とサイズ

- 企業分析・投資判断の統合では **買わない理由 3 つを推論より先に** 置く。
- 確信度 `低` では通常サイズを提案せず `低確信度のサイズ`（既定「通常の半分」）。サイズは金額で、**単位は万円**（`専属エキスパート` の `1銘柄あたり金額`・`許容損失` は万円の数値列。式: `min(1銘柄あたり金額, 許容損失 ÷ 破綻幅)`）。価格の値を使う計算は式だけ示す。
- 制約4項目が空のままスクリーニングしない（`不足 CONSTRAINT_EMPTY:<列名>`）。

## 7. 参照データのライセンス境界（`docs/ai-advisor/reference-data.md` §1 が正本）

- 書けるのは **commercial-ok（EDINET 由来）・factual-cite（TDnet 由来: 表題・日付・分類・URL。自作要約の優待内容）** だけ。
- **personal-only（Yahoo / JPX / 日証金 由来）** — 株価・出来高・RSI・PER・PBR・利回り・信用残高・倍率・スコア・市場区分・JPX 業種 — は **値も、値を復元できる記述も書かない**。`成立／未成立` と「参照資産『名称』で確認（値は転記しない）」だけ。読んで判定に使うことは可。エントリー帯は条件文、サイズは金額で表す。
- **no-store（みんかぶ由来の掲載原文）** は読まない・どこにも書かない。
- 業種は EDINET 由来の 33 業種だけ。`market` は書かない。実在銘柄コードと区分の対応表を作らない。
- 事実台帳（`銘柄` 本文）に書くのも commercial-ok / factual-cite の事実だけ。

## 8. データ読み込みの原則（観点単位・全表読み禁止）

- **データ全体をコンテキストに載せない。** `分析観点` を 1 つずつ: その観点の **スライス**（参照資産の `パス・URL` ＋ `クエリ=` / `項目=`（≤12 列）/ `件数=`（`取得上限` 既定 30・最大 100）/ `期間=` / `節=`）だけをシェル（`curl` ＋ `jq`）で取り、切ってから読む → 要約（≤600 字）・寄与・根拠 3 行・確認不能 を本文の節に書く → **生データと一時ファイルを捨て、以後参照しない** → 次の観点。統合は本文の観点の節だけを入力にし、再取得しない。
- **全表読みの禁止（ハードルール）**: `limit` なしの API 呼び出し、全銘柄ループ、全ページ送り、`SELECT *`、`LIMIT` なしの SQL、`日次タスク`／`判断`／`銘柄`／`ルール` DB の総なめ、R2／D1 のダンプ、PDF・HTML の全文読み。DB クエリは必ずフィルタ（状態・対象日・利用者）＋`limit`、ページは `fetch` 1 件ずつ。
- Notion の読みの上限: 専属は必要列のみ／ルールは共通節＋`## 観点: X` 節／観点本文 300 字／銘柄本文 最新 30 行／前回タスク 統合節のみ／過去判断 20 行。
- 1 ランの上限: 朝レポート タスク 10 行、観点 `軽` 8／`重` 1 ／ タスク。夕振り返り 利用者 10 人、追跡判断 30 行／人。随時実行 Webhook 1 行・ポーリング 5 行。上限に達したら `実行中`＋`完了観点` で止め、次のランで再開する。
- 参照資産に到達できない・フィールドが無い → `不足` にしない。その観点を `確認不能` にして次へ。応答形の不一致は実行サマリーで `参照資産.提供データ`／`分析観点.スライス` の修正を提案する（自動化は変えない）。
- 認証が要る経路（D1 REST、R2 直読）は `参照資産` が `有効` かつ Secret 配布済みになるまで使わない。

## 9. 自己検査（統合を書く前・仕上げの前・振り返り保存の前に必ず）

1. 禁止語（§3）が本文・`AIの一言`・`要約`・`追跡メモ` にないか（例外の引用以外）。
2. personal-only の値（株価・出来高・RSI・PER・PBR・利回り・信用残高・倍率の数値）や、みんかぶ由来の掲載文が本文・事実台帳・列・実行サマリーに出ていないか。
3. 出典 URL と基準日のない数値がないか（無ければ `確認不能` になっているか）。
4. 企業分析・投資判断で「買わない理由 3 つ」が推論より前にあるか。IF-THEN が条件文で「指示ではない」と書かれているか。免責が尾にあるか。
5. `判断.最終判断`・`判断メモ` を書いていないか。`ルール.状態` を `発効`・`棄却` にしていないか。`分析観点`・`参照資産` を書いていないか。
6. `## 観点: X` の見出しが `分析観点.観点名` と一致し、節の数が `完了観点` と一致するか。`適用ルール` が実行開始時の `発効` 行を指すか。
7. 各観点の取得が `取得上限`・`項目=`・`期間=` の範囲内だったか（`limit` なし・全表読み・全ページ送りをしていないか）。要約が 600 字以内か。
8. リポジトリ変更・PR・Slack 等への投稿・シークレット値の出力がないか。
